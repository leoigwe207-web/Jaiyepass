# JaiyePass local auth + nationwide copy + interaction patch

This package targets the JaiyePass V2 / production rebuild previously supplied and installed. It contains only changed files. It does NOT contain a database migration, GitHub push, or production deployment.

## What was changed
- Sign-in/signup/reset account interface: editorial split-screen desktop, clean mobile layout, accessible inputs/buttons, consistent errors and messages.
- Reusable Show/Hide password control on sign-in, signup and new-password forms.
- Real password reset end-to-end: Supabase sends its configured recovery email; callback forwards to `/update-password`; logged-in recovery session can update the password. Removed second misleading reset email.
- Auth actions now fail gracefully for missing config, and signup checks service-role config before creating accounts.
- Supabase Dashboard-created users with no profile are backfilled after successful login with `attendee` role; existing `admin` role is never overwritten.
- Nationwide copy for host onboarding, about, and footer; no Victoria Island office claims remain in public contact or privacy pages.
- Subtle hover/active/focus effects and reduced-motion support, no new dependencies.

## Install from project root in VS Code PowerShell

```powershell
Expand-Archive "$HOME\Downloads\JaiyePass-Auth-UX-Nationwide-Fix.zip" -DestinationPath "C:\Users\David\Documents\JaiyePass" -Force
powershell -ExecutionPolicy Bypass -File .\release\setup-local-auth.ps1
node .\release\check-local-auth.mjs
npm.cmd run build
npm.cmd run typecheck

npm.cmd run dev
```

**Back up your existing project files or commit your working changes before extraction. If the ZIP lands in another download directory, adjust the first command.**

### Required environment variables
Get these from the **correct Supabase project** (not your personal access token):
- `NEXT_PUBLIC_SUPABASE_URL`: project URL (public).
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`: publishable/legacy anon key (public). The current `createServerClient` code expects the configured project's supported public key.
- `SUPABASE_SERVICE_ROLE_KEY`: server-only secret used by secure profile-setup code, never `NEXT_PUBLIC_`.
- `NEXT_PUBLIC_APP_URL=http://localhost:3000` for local development.

The PowerShell script asks for keys without displaying the input and writes `.env.local` only on your computer; `.env.local` is gitignored. Do not share the resulting file or credentials.

For production, set your official production URL, preserve existing secret keys, and configure the correct Supabase Auth redirect allowlist (`http://localhost:3000/auth/callback`, your deployment's `/auth/callback`, plus any `/auth/confirm` paths required by email templates).

### Tests to perform before deploying
1. Visit `/signup` and create a real **test** user; verify email confirmation and that a profile exists in `public.profiles` with `attendee` role.
2. Sign in with your existing admin credentials and visit `/admin`. Confirm admin permissions are retained.
3. Use Show/Hide on signup/login, keyboard Tab, mobile device sizes.
4. Request a password reset; verify the email arrives and link reaches `/update-password`. Check changing password and signing in again.
5. Verify selling-ticket links require login as appropriate and `service_role` never appears in browser source.
6. Confirm real Paystack and Resend configurations independently. This patch does not enable payment or email infrastructure.
